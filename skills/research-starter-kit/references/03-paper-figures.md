## 09 · 论文画图指南

### 9.1　总览

> **提示**　好的论文配图应该帮助审稿人快速回答三个问题： 这篇论文解决了什么重要问题？ 现有方法为什么不够好？ 你的方法有什么优势？效果如何？ 很多审稿人第一次接触论文时，会先扫一遍标题、摘要、和论文的图表。因此，图画得好不好，会直接影响论文的第一印象。好的论文配图，能让读者在几秒内抓到论文的核心贡献。

一般来说，一篇文章的科研图表主要分为：

- 动机图：通常出现在论文开头附近，用来展示论文的核心动机、问题观察或方法优势，主要作用是快速引起读者的兴趣，让读者产生“这个问题确实重要，而且这篇论文的思路有意思”的感觉
- 方法图：包括架构图、算法示意图、数据构造图等
- 实验图：包括实验表格、柱状图、折线图、散点图、热力图、雷达图、案例可视化等

前两者可以通过写提示词用AI先生成草图，再按照草图复现（使用PPT或Visio等等）自己修改微调；第三个则可以用coding agent写代码生成图表。

### 9.2　动机图（Teaser Figure）

一般放在论文的开头或者Introduction中，对于Teaser Figure，通常只需要围绕两个重点展开：

- 问题或观察：论文要解决的问题？or 现有方法的局限？or 典型的、代表性的、反直觉的失败案例或观察
- 本文的优势：本文方法的优势是什么？

动手画图之前，先想清楚一句话：

> **提示**　读者看完这张图，应该记住什么？

如果这一句话想不清楚，图通常也画不清楚。

基本原则：做到Self-Contain，即读者只看这幅图，不需要去翻阅论文其他内容，也能明白在讲什么。

> 图 9-1　动机图（Teaser Figure）的经典版式：左边现有方法的失败，右边本文方法的优势（ 示意图 ）　图示要点：现有方法 | 本文方法 / 失败案例 A / ← 问题 / 观察 / 方法 D：核心优势 / 带来什么改善 / 效果如何 / 优势 / 局限 B | ← 为什么不够好 / 一句话原则：先说清「问题是什么、你凭什么更好」，再动手画 / Self-Contain：读者只看这一张图、不翻正文，也能明白在讲什么

| 区域 | 它承担什么 | 可抄的点 |
| --- | --- | --- |
| ① 设定区 | 交代任务与指令：机械臂、三个纸盒、一句引号内的自然语言指令 | 指令照原文抄、不改写；用图标标明「指令是人给的」，避免读者误解为系统自带目标 |
| ② 基线行 | 展示现有方法的失败瞬间 | 失败要具体到可观察事件（「Carton topples!」），不要说「performance is poor」 |
| ③ Ours 行 | 展示本文方法的成功过程 | 放最下方；用 3 帧连续动作构成因果链，比一句结论有说服力 |
| ④ 语义色 | 把「错」标出来 | 全图只留一处高饱和红，其余颜色全部让给实物本身 |

#### 配色核查：这张图几乎没有「配色」，这恰恰是它的高明处

| 维度 | 做法 | 评价 |
| --- | --- | --- |
| 主色来源 | 全靠实拍物体的白 / 蓝 / 橙 | 真实物体自带颜色，不再叠色板 —— 这是 teaser 图最省力也最高级的解法 |
| 语义色 | 只有红色，且只用于「倒了 / 失败」 | 单一语义、不滥用；没有把红绿蓝紫全堆上去 |
| 背景 | 纯白 + 浅灰桌面 | 让红色和画面主体成为唯一焦点，视觉噪声极低 |
| 双编码 | 红框 + 文字「Carton topples!」 | 不依赖颜色单独传意，色盲友好（红对红绿色盲不敏感，但有文字兜底） |
| 情绪符号 | 🙁 / 🤓 | 记忆点强，属「风格冒险」；需备一版不含 emoji 的图，防止某些模板渲染成方块 |

#### 可直接抄的五个细节

1. **分隔用虚线不用实线**——轻，不抢画面；
2. **唯一变量原则**：两行除方法外，机位、光照、物体、指令全部一致；
3. **三帧胜千言**：用「动作发生了」证明能力，而不是用形容词；
4. **位置即等级**：Ours 永远在下 / 右，落在读者视线的终点；
5. **Caption 四件套**：`Figure 1.` + 加粗小标题 + 一句总述 + `(left)/(top)/(bottom)` 定位 + 优势陈述。

#### 我会改的四处

1. 红色只出现在基线侧，Ours 侧没有任何正向色 —— 视觉重量反而压在「失败」上。可给 Ours 行加极淡色细边框或小对勾，别用饱和绿，避免红绿对撞；
2. 两个行标签基线不齐（Vanilla 居中、Ours 偏左），版面显散 —— 两个标签左对齐到同一列；
3. 缩成缩略图后三帧动作差异看不清 —— 加一个 zoom-in 小圈，圈出「纸盒被推倒」的接触点；
4. 线性人形图标与彩色 emoji 风格不统一 —— 二选一。

> **提示**　一句话总结：**数据图用色板，teaser 图用实物色 + 一个语义色。**两者是不同规则 —— 很多人在实拍照片上叠一堆彩色箭头和高饱和标签，结果比原图更乱。

#### 配色核查：靠「形状 + 排版」而不是靠颜色

| 维度 | 做法 | 评价 |
| --- | --- | --- |
| 底色 | 纯白 + 浅灰，无高亮块 | 三行信息密度高，背景不能再抢；转灰度印刷也不失真 |
| 判定色 | 只有绿勾 / 红叉，且勾叉形状本身即语义 | 颜色只是 / 冗余编码 / ，色盲读者靠形状照样读懂 —— 红绿是最危险的组合，这里用形状救了回来 ✅ |
| 模型图标 | 三行同一个「书堆」图标，仅标签不同 | ⚠️ 与基线无法一眼区分，必须读到标签才知道换模型了 |
| 强调手段 | 无彩色箭头、无描边高亮 | 靠垂直对齐和留白组织版面，是最「耐看」的做法 |
| 判定列 | 三个符号垂直对齐成一列 | 可以「竖着扫」：2 错 1 对的结构在 1 秒内可见 |

#### 可直接抄的五个细节

1. **判定符号单独占一列并垂直对齐**——这是整张图最实用的技巧，比任何配色都有效；
2. **虚线只用在任务域切换处**，同为立体几何的第 2、3 行之间不画线，用留白分组（分隔线是分组工具，不是行装饰）；
3. **每行内部阅读顺序固定**：题目图 → 模型 → 答案 → 判定，四个位置在三行完全一致；
4. **答案加引号**，模拟模型原话，强调「这是它真说的」，而不是作者转述；
5. **Caption 用 (top)/(middle)/(bottom) 定位**，一句话写清「在哪失败、在哪成功、本文做了什么」。

#### 我会改的五处

1. **LaTeX 源码漏进图里**：左图残留 `\angleOAB=40°`，题干里写着 `\theta` —— 渲染前必须逐字核对，截图拼图时最容易出这类事故；
2. **ours 与 baseline 用同一个图标**，只靠标签区分 —— 至少换个色或加细边框，否则读者读到标签才知道换了模型；
3. **答案形式不对等**：50°（数值）/ arccos0.9333（四位小数近似）/ arctan(3/√205)°（精确式）—— 建议统一精确式，或给近似值标 `approx`，读者才分得清「错的是数值还是表达」；
4. **Caption 有漏词**："while showing performance in plane geometry" 应为 "while showing **strong** performance" —— caption 是审稿人必读，务必单独校一遍语法；
5. **第三行左侧题干没有题目框**，与前两行的浅灰框不一致，三行左列基线也略有错位。

> **提示**　**案例 1 vs 案例 2 的分工：**案例 1 是「同一任务的纵向对比」，胜在直观；案例 2 是「用排除法界定能力边界」，胜在严谨——它先堵住了「你的基线本来就不行」这个最致命的反驳。**如果你的贡献是「在某个特定子问题上更好」，优先用案例 2 的结构。**

### 9.3　方法流程图（Main Figure)

> **提示**　清晰展示论文所提出的方法，让读者能够理解整个工作流以及核心的贡献

画图工作流：

- 先用一句话写清楚这张图要表达什么，作为该图的caption
- 列出必须出现的元素以及相应的流转关系，例如输出、输出、核心模块，中间信息是怎么流转的
- 画出大致布局，是上下分层、左右对比还是原型闭环？主流程从上到下还是从左到右？核心贡献放在哪里？
- 模块化和命名，把大块内容拆成清楚输入输出的模块，并给每个模块起一个名字。模块名字应当简短凝练，与正文一致。
- 统一视觉语言，确定颜色、形状、箭头、字体和图标风格。

核心原则：

- 要像写代码一样模块化流程图，即，把方法拆成若干个有清晰输入输出的模块
- 每个模块有一个清楚的命名，应当与正文术语保持一致
- 模块之间要有箭头表示明确的流动关系，比如：数据的流动、反馈信息、训练先后顺序等等，不同的含义的箭头最好用不同样式区分，例如实线箭头表示主流程，虚线表示反馈，红色表示监督信号，灰色表示辅助信息等。
- 用颜色和形状辅助信息区分，同类模块使用同一种颜色，不同功能模块可以使用不同形状，颜色控制在3-5种，不使用高饱和度、高亮度的颜色。

#### 3. 矢量图标与素材库（适用于概览图/流程图）

概览图和流程图需要大量的概念性图标（如服务器、大脑、数据流、对比符号），使用统一风格的矢量图标（SVG/EPS）是保证“字体统一，风格一致”的关键

- Flaticon ([https://www.flaticon.com/](https://www.flaticon.com/))：全球最大的免费矢量图标库。画概览图时，建议直接在里面搜索“Icon Pack”（图标包），确保整张图中的设备、用户、箭头等元素属于同一种设计风格（如皆为线条风或皆为扁平风），避免画面杂乱
- iconfont-阿里巴巴矢量图标库 ([https://www.iconfont.cn/](https://www.iconfont.cn/))：国内最强大的图标库，中文搜索极度友好。拥有海量由设计师打包好的开源图标库，支持免登录下载SVG/PNG
- The Noun Project ([https://thenounproject.com/](https://thenounproject.com/))：主打极致简约、高度概括的黑白符号图标。如果你的论文概览图追求高级的极简风，这里的素材是绝佳选择
- BioRender ([https://biorender.com/](https://biorender.com/))： 拥有海量专业的细胞、分子、实验设备矢量素材，支持拖拽拼装，堪称生物医学界的“PPT”

#### 4. 专业流程图与架构绘图工具

绘制“方法流程图”时，你需要强大的对齐、吸附和连线功能，确保箭头没有交叉、方向统一

- Draw.io / Diagrams.net ([https://app.diagrams.net/](https://app.diagrams.net/))：完全免费且开源的强力绘图工具。拥有极其丰富的网络、云架构、通用流程图组件。支持网页版和桌面端，可直接导出为不失真、可二次编辑的 SVG 或 PDF 格式，是替代 Visio 的绝佳选择。
- ProcessOn ([https://www.processon.com/](https://www.processon.com/))：国内主流的在线作图工具，上手极快。其“模板中心”有大量学者分享的现成科研流程图、系统架构图，可直接克隆修改。
- Lucidchart ([https://www.lucidchart.com/](https://www.lucidchart.com/))：功能极度丝滑的团队协作绘图软件，其连线的智能避让和排版对齐功能非常强大，适合处理复杂的系统多模块交互图。

#### 5. 实验数据图表代码与可视化库（适用于实验图表）

趋势图、柱状图等可以用 coding agent 写代码生成，给 Agent 发送指令时，指定以下业界标杆库，能让生成的图表自带高级感。

- Python - Seaborn & Matplotlib：科研界的老牌标杆。Seaborn 在 Matplotlib 的基础上进行了高级封装，自带多套极具学术感的学术主题主题（如 whitegrid），其默认配色比 Matplotlib 更现代。
- Python - ProPlot ([https://proplot.readthedocs.io/](https://proplot.readthedocs.io/))：专门为发表高质量学术论文设计的 Matplotlib 包装库。它极大地简化了多子图（Subplots）的排版对齐、标签共享以及学术配色的调用。

#### 6. 善用 AI 绘图与草图生成（适用于概览图创意）

方法流程图之类可以通过 AI 先生成创意草图，再手动复现修改。

- GPT-Image-2 / Midjourney / DALL-E 3：在生成方法概览图（Teaser Figure）的草图时，可使用提示词定义结构（例如："A structured, 3-part scientific diagram from left to right, clean background, pastel color palette, vector style..."）来获取排版和视觉引导的灵感。
