## 01 · 如何做科研？

> 图 1-1　科研工作流程（ 示意图 ，据原文「研究生的主要任务」整理）　图示要点：科研工作是一个闭环：任何环节发现问题，都可回到上一环节 / 找论文 | 读论文 | 想 Idea | 做实验 | 写论文 | 投稿 / 摸清方向 | 批判性阅读 | 找真问题 | 验证可行性 | 讲清贡献 | Rebuttal / 被拒 / 审稿意见 → 补实验或换角度，回到「想 Idea」

### 什么是研究（Research）

研究广义上可以理解为：通过可重复性的观察和可验证性的结果，能够对人类认识世界做出独创性且具有影响力的贡献。在人工智能领域，包括但不限于：

1. **发现新知识**：新理论、新模型架构、新算法。
2. **解决新问题**：使用新技术、新设计、新方法、新模型等解决实际问题。

### 如何评判研究工作的创新性与影响力

如果所做研究只是在已有工作基础上的简单推导或改进（大部分同学的工作），其创新性和影响力一般会大打折扣。一篇非常重要、影响力极大的文章，一般有如下特点：

- **抓住领域发展的关键问题**，提出新方法且相较现有方法有很大优势：如 ResNet 缓解深层神经网络梯度消失、Transformer 缓解 RNN 长序列依赖和并行化难题。
- **为以后的工作奠定基础，或开辟新方向**：如 GAN 提供了一种新的图像生成范式。
- **在公认任务上具有显著性优势**：如 AlexNet 获得 ImageNet 竞赛冠军、AlphaGo 战胜人类职业棋手。

### 研究生的主要任务

1. **探索和构思新想法**，确保研究创新性：充分了解相关领域最新发展，做大量文献检索与阅读。
2. **将新想法付诸实验**，检验可行性：需要深入严谨的实验分析与快速的代码实现能力。
3. **撰写成文并投稿**：AI 领域论文通常投学术会议，经同行评审、Rebuttal 决定录用；需不断提高写作与表达能力。
4. **评审他人论文**：会议要求作者也必须是审稿者，完成身份转变，评判他人工作的创新性与影响力。
5. **参加学术会议**：分享论文、学习新成果、交换想法、寻求合作。
6. **申请奖学金与项目经费**：很多经费面向研究生甚至本科生，对拓展人脉、提高影响力、改善生活都有帮助。
7. **协助指导低年级学生**：高年级博士生与导师协作指导新人，是博士的额外必修课。
8. **参与项目研发**：参与课题组纵向/横向项目，把研究成果应用于真实场景。

## 02 · 如何找论文？

1. **从重要会议和期刊中寻找论文** AI 方向以会议论文为主。每次会议放榜后都可以看到全部文章列表；OpenReview 的会议还能看到所有投稿。每次投稿截止和放榜之后，都应对相关文章做一次筛选和阅读。常见 venue：

    | 方向 | 会议 / 期刊 |
    | --- | --- |
    | 机器学习 | ICML、NeurIPS、ICLR |
    | 自然语言处理 | ACL、EMNLP、COLM |
    | 计算机视觉 | CVPR、ICCV、ECCV |
    | 人工智能 | AAAI、IJCAI |
    | 数据挖掘与信息检索 | KDD |
    | 综合性高影响力期刊 | TPAMI、JMLR、TMLR、TKDE、Nature Machine Intelligence 等 |

    > **提示**　以上名单不是固定的，也不是评价论文价值的唯一标准。进入具体方向后，应根据导师建议和领域引用习惯，建立自己的重点 venue 列表。

2. **从「种子论文」开始扩展** 刚进入一个方向时，先找到几篇「种子论文」，再以它们为中心扩展。适合作为种子论文的通常包括：
  - 近几年发表的高质量 Survey；
  - 该方向公认的代表性工作；
  - 与自己研究问题最接近的论文；
  - 被广泛使用的 Benchmark 论文；
  - 最近两年顶会中的代表性论文；
  - 导师或同学推荐的论文。
3. **沿着论文的文献网络「顺藤摸瓜」** 读一篇文章不只是读这一篇，而是以它为引子，通过 Introduction、Related Works、Compared Methods、References 等去找更多相关文章：
  - **向后追踪**：查看论文引用了哪些早期工作；
  - **向前追踪**：查看后来有哪些工作引用、改进、质疑或扩展了这篇论文。
4. **关注作者、课题组和研究团队** 读论文过程中关注作者课题组信息。如果某个课题组和你方向一致，大概率他们会有一系列相关文章和做这个方向的学生。

## 03 · 如何读论文？

> **提示**　每个 Topic 的发展历程都是无数聪明人智慧和汗水铺就的，其中有一条前后衔接的线索。某一天当你把头脑中杂乱的东西串成一线，就会顿时豁然开朗——「啊，原来是这样！」这时你就开始尝到研究带来的乐趣了。

### 如何读论文（七步法）

> 图 3-1　读论文的步骤（ 示意图 ；原文标称「七步法」，此处按抓取到的 6 步绘制，完整版见原文链接）　图示要点：宏观概览 / 1 / 先看摘要 + 翻图表，判断这是什么类型的工作、解决什么问题 / 锁定核心研究问题 / 2 / 问题可能在 Abstract，也可能藏在 Introduction 转折处——先找到它 / 梳理已有工作 / 3 / 别人怎么解的？还差什么？如果换我来做，我会怎么做？ / 阅读文章所提方法 / 4 / 带着批判眼光，比较「作者的解法」和「你想到的解法」的优劣 / 分析与复现实验 / 5 / 数据集、baseline、指标是否公平全面？关键论文要读代码复现 / 顺藤摸瓜 / 6 / 沿 Introduction / Related Works / 参考文献扩到整个研究背景

1. **宏观概览**：不要上来就一字一句从头读到尾。先浏览摘要、翻看图表，建立基本认识——什么单位发表？什么类型的工作？解决什么问题？效果大概如何？
2. **锁定核心研究问题**：学术论文的核心是它要解决的研究问题。好论文都围绕一个清晰、具体的问题展开——可能在 abstract 中，也可能在 Introduction 转折的某一段中，先找到它。
3. **梳理已有工作**：主动思考——这个问题是不是真实存在的？有哪些人研究过？现有解决办法是什么？还存在什么挑战？如果让我来做，我会怎么做？
4. **阅读文章所提方法**：仔细推敲论文方法，评判作者的解法与你所想解法的优劣；以批判的眼光找局限性，从中挖掘新想法，思考如何改进和超越。
5. **分析与复现实验**：分析实验——用了什么数据集？和什么方法对比？设置是否全面？结论是否合理？有没有开源代码？关键论文要读代码并尝试复现。
6. **顺藤摸瓜**：以文章为引子，结合 Introduction、Related Works、Compared Methods 了解整个研究背景，顺藤摸瓜学习尚未掌握的技术、方法、概念。

## 04 · 如何想 Idea？

想 Idea 主要分两步：**选择一个好的研究问题**，**寻求问题的解决方案**。

### Problem-driven vs Method-driven

- **Problem-driven research**：找到重要的问题或目标，想办法把它做好。例如：大模型在某任务上性能不好，先确定 1–2 个 benchmark，探索各种技术，目标就是把任务做 work；也可以构建新 benchmark，把一个问题定义清楚（如游戏 Agent 方向，还没有 benchmark 支持某类评估时，定义一个新 benchmark）；或在通用 benchmark 上对已有方案做问题分析，找到关键挑战（如 GRPO 的效率问题、信用分配问题），再改进优化。
- **Method-driven research**：拿着锤子找钉子——基于已有技术方案不断解决新问题。例如 GRPO 刚出来时拿来做多模态推理、Agentic RL；某个技术火的时候去解决数学、医疗、司法垂域问题。

> **提示**　两种方式很多时候要融合。大部分情况下更偏好 Problem（Goal）-driven research，在这个过程中对 method 进行适配和优化。

### 如何找到研究问题？

1. **批判性论文阅读**：阅读时「鸡蛋里挑骨头」，多思考论文的不足，把「读文献」和「提问题」绑在一起而不是分成两个阶段，主动思考「换个数据/换个假设会怎样」。这个习惯越早养成越好——很多研究生前两年读了大量文献却提不出问题，就是因为只在「理解」、没有「批判性质疑」。
2. **从失败中寻找机会**：思考主流方案有哪些 failure case，主动寻找和复现 failure case，深入分析原因，尝试提出解决方案。
3. **从「是否有效、为什么有效」反推机制**：对效果好但缺乏解释的方法主动追问「它内部到底在做什么、为什么 work」，通过实验做算法分析。这类 reverse-engineering 式问题往往比「设计一个新方法」更容易找到切入口——你有一个已确定有效的现象作锚点，只需设计实验或理论工具去拆解它。

## 05 · 如何进行学术汇报

### 学术汇报的形式（PPT）

汇报 PPT 不需要炫酷动画，但要基本美观：

- 中英文字体统一合理：中文可用雅黑、幼圆，英文可用 Calibri、Times New Roman 等；
- 字号行距合理：标题 32–36，正文 18–24，行距 1.2–1.5；
- 每页不要出现大段文字，每部分文字少于 3 行（重要引用除外）；讲 PPT 时不要逐字读；
- 重要部分用高亮颜色、底色框吸引注意力；
- 设置目录页、导航页；
- 图片可以让 AI 生成，但要确保内容和逻辑正确；
- 更多技巧可参考斯坦福《如何做好学术报告》（B 站可搜）。

### 学术汇报的内容

1. **选择高质量文章**：AI 论文很多，需要做价值判断——你有没有从中学到新东西？希望听众学到什么？后续是否打算 follow？
2. **也可以做方向 Tutorial**：介绍与研究方向相关的新热词及工作发展脉络。
3. **站在听众角度**：组会分享要让 80% 以上的人听懂，根据受众决定是否补充前置知识。
4. **汇报思考框架**：
  - **总体贡献**：能否用 2–3 句话总结？「针对 xxx 问题，提出了 xxx 方法，在 xxx 任务上取得了 xxx 性能」。
  - **动机**：解决什么问题？是很多人研究的问题还是新问题？如果是前者，相关工作分几类？本文核心优势/创新点是什么？如果是新问题——它真实存在还是臆想？什么场景会遇到？解决它有什么好处？有没有简单方法可以解决？
  - **方法**：主要流程是什么？从输入到输出经过几步？系统怎么运行？包含哪几个模块？

## 06 · 如何高效 Meeting

### 为什么要 Meeting

- Meeting 是为了更高效推进科研，不是简单的工作进度汇报。科研过程中会有试错和没有进展的情况，不要把 Meeting 当成压力。
- Meeting 的核心目标不是「证明自己做了很多」，而是**暴露问题、澄清思路、获得反馈、推进工作**。
- 除定期 Meeting 外，有任何需要讨论的进展或问题都可以随时约时间，培养有问题就讨论的习惯。

### 组织形式

1. **针对在推进的 Project**：以 Project 为单位 Meeting，Project leader 负责协调时间、约会议。每个 Project 维护一个文档：要做的事情、Technical Contribution、时间规划、成员分工、当前进展、实验结果和存在的问题——凝练要点，不要长篇大论。
2. **个人学习阶段**：维护个人进展文档——正在关注的事、读的论文（凝练核心观点）、个人思考和讨论。
3. **频率**：在推进的 Project 至少 2 周一次，有重要结果可随时约；博士生和硕士生至少 2 周一次，实习研究生和本科实习生至少 1 个月一次。

### Meeting 模版（每次 Meeting 前整理）

1. Review 项目大方向和 Contribution，反思自己是否在正确的道路上；
2. 回顾上次 Meeting 的结论和 Todo；
3. 总结上次以来的进展——三句话以内讲清楚；
4. 列出想讨论的问题、有意思的实验现象和观察；
5. 分享几篇最近读的论文，附一句话总结。

## 07 · 一些好的习惯

1. **保持稳定的学术输入**：每天工作前抽 10–20 分钟，浏览相关 arXiv 分类、Hugging Face Daily Papers、会议论文列表或学术平台推荐，了解新论文、新问题、新方法。
2. **建立自己的知识积累系统**：有价值文章（idea 有启发性、实验效果好、写作好等）存储管理起来，可用 Zotero、飞书、多维表格等工具。
3. **记录实验日志**：每次重要实验记录——实验目的/待验证假设；相比上一组实验修改了什么；数据、模型和参数配置；随机种子及运行环境；核心结果；是否符合预期；当前结论；下一步做什么。**失败实验和负面结果同样要记录**——帮助排除错误方向，避免几周后重复相同的尝试。
4. **问题与解决方案记录**：遇到的问题及解决方法及时记录，避免重复排查，也方便帮助团队其他同学。即使暂时没解决，也应记录已尝试过的方法。
