# 科研入门指南（Research Starter Kit）

这是一套判据与改写动作库，不是模板库。用户拿草稿来，先判定它违反了哪条标准，再按标准给出具体改法。

## 一、先路由，再回答

| 用户想做的事 | 读哪个文件 |
| --- | --- |
| 选题、找论文、读论文、想 idea、组会/汇报、与导师 meeting、研究习惯 | `references/01-research-workflow.md` |
| 写或改 Abstract、Introduction、Related Works、Methods、Experiments、Reference | `references/02-paper-writing.md` |
| 画 teaser 图 / 方法图 / 结果图表，选配色，写 caption | `references/03-paper-figures.md` |
| 回复审稿意见、写 AC message | `references/04-rebuttal.md` |
| 学术会议参会、奖学金、AI 辅助科研、延伸书单 | `references/05-academic-life.md` |

规则：

- 涉及"这一节该怎么写""这张图该怎么画"时**先读对应文件再回答**，引用其中的判据与案例，不要凭通用写作常识泛泛而谈。
- 复合请求（例如"帮我改摘要并配一张 teaser 图"）要分别读 `02` 与 `03`，不要只读一个。
- 用户提问只要一句话结论（如"reward 曲线该用什么图"），读文件后直接给结论 + 一句理由，不要复述整章。

## 二、三条贯穿全流程的原则

1. **论文是贡献说明书，不是工作记录。** 读者要能回答三件事：解决什么问题、提出了什么关键思想、这个贡献对领域意味着什么。凡是"我们做了 A，然后做了 B"的流水账式段落，一律按贡献链条重排。
2. **结构先于文字。** 每节承担固定功能（摘要=贡献说明书、引言=漏斗、方法=为什么这样设计、实验=claim 的证据）。结构不对时不要先润色句子，先把段落功能对齐。
3. **审稿人只读一遍。** 摘要在前 3 句、图在第 1 眼就要传达核心 claim。判断任何改动时问一句：这会不会让"只读一遍的人"误解或抓不到重点。

## 三、按节写作的硬判据（速查）

- **Abstract**：五句话原则 —— 背景 1 句、科学问题 1–2 句（**最关键**）、方法思想 1–2 句、可量化结论 1 句，外加闭环检查（结论必须回扣提出的问题）。问题若是"LLMs often fail in xxx"这种经验现象，就掉到 borderline；要上升到机理层面（理论缺陷 / 泛化弱 / 稳健性不足）。
- **Introduction**：四段漏斗 —— 领域为何重要 → 已有工作做到哪 → 缺口是什么 → 本文做了什么、怎么做、结果如何。禁止开篇就讲自己的方法。
- **Related Works**：按"分类 + 对比"组织，为缺口铺垫；不做流水账罗列，每类结尾要落到与本文的差异。
- **Methods**：先讲动机与直觉，再给形式化定义；每个模块回答"为什么需要它"，而不是只写"它是什么"。
- **Experiments**：每个实验对应一条 claim；主实验证明 SOTA，消融证明每个部件的必要性，分析实验解释机理。表格要标出对比对象与设置差异。
- **Reference**：只引真正读过的；格式统一；避免堆砌无关引用凑数量。

细节、正反案例与句式，见 `references/02-paper-writing.md`。

## 四、画图

三类图各有判据：**动机图（teaser）**只讲"问题或观察 + 本文优势"；**方法图**讲清模块与数据流；**结果图**要让趋势一眼可见。

动手前必须能写出一句话："读者看完这张图应该记住什么。" 写不出来就别画。

硬性要求：

- **Self-Contain**：只看这一张图、不翻正文，也能看懂。缩写首次出现即展开。
- **语义色单一**：全图只留一处高饱和色用于"错 / 失败 / 本文优势"，其余颜色让给内容本身。优先色盲安全色板（Okabe-Ito、Tableau 10）。
- **双编码**：不要只靠颜色传意，配图形或文字兜底。
- **矢量导出**：优先 SVG / EPS / PDF；导出后缩到论文双栏实际尺寸再检查一次字号与线宽，肉眼在小尺寸下不清就是不合格。
- **Caption 四件套**：`Figure N.` + 加粗小标题 + 一句总述 + `(left)/(top)/(bottom)` 定位 + 优势陈述。Caption 是审稿人必读，单独校一遍语法。

案例拆解、配色表与工具清单见 `references/03-paper-figures.md`。

## 五、Rebuttal

- **不漏点**：逐点回应，类似意见可合并，但不得因篇幅删点。
- **揣摩倾向**：明说"补了 xxx 就提分"的审稿人优先满足；给 positive 的巩固，给 negative 的投入最多篇幅；利用审稿人之间的矛盾（A 批评的 novelty 恰是 B 称赞的点）。
- **先抓 factual error**：审稿人有事实性错误时，第一句就指出，同时同步 AC，降低该意见在 AC 心中的置信度。
- **篇幅是资源**：能缩写的缩写，把字数留给最可能翻盘的审稿人。
- **结构**：先总述共性问题，再逐审稿人回应，末尾列出承诺的修改。
- 语气克制，不情绪化；不复述审稿意见原文。

策略细节、常见问题（novelty / factual error / 涨点有限 / 实验不足）与英文句式模板见 `references/04-rebuttal.md`。

## 六、交付前自检

**稿件**：摘要能否独立读懂并说出贡献？引言第 1 段是否在讲领域而非自己的方法？每个实验是否对应一条 claim？所有宣称的贡献是否都有证据？

**图表**：每张图能否用一句话说明用途？缩小到双栏尺寸后文字是否仍清晰？是否有只靠颜色区分的信息？caption 是否交代了 (a)(b)(c) 各是什么？

**Rebuttal**：是否每条意见都有回应编号？承诺的补充实验是否写明"将在 final version 中提供"？是否有一处情绪化表达？

## 七、边界

- 只做诊断、结构重排与表达改写；**不代写研究贡献，不编造实验数字，不虚构参考文献**。引用需可核实，拿不准就标注"待核实"。
- 用户给中文草稿但目标是英文投稿时：先对齐逻辑骨架，再处理英文表达，不要直接逐句翻译。
- 手册内容以原作者（南京大学郭兰哲老师等）的公开资料为基础，涉及具体领域惯例时应提示用户以本领域最新要求为准。
